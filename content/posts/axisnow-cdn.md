## 一、前言：海外 CDN 与 Cloudflare 差在哪

给站点做加速，大多数人第一条路是 Cloudflare 免费版。它确实慷慨——免费 CDN、免费证书、免费 DDoS 防护、免费 WAF，几乎是白送一整套边缘服务。但只要你的访客里有中国大陆用户，就会撞上几堵墙：

**1. 中国大陆没有 Cloudflare 的 PoP。** 大陆访客的请求只能被 Anycast 甩到香港、圣何塞、洛杉矶等地。白天还能忍，晚高峰国际出口一拥塞，绕路、丢包、被 QoS 限速接踵而至。你 ping 一下自己的 CF 域名，经常能拿到 150~300ms 的成绩，而同样一台放在香港 CN2 的机器可能只有 40ms——差距不在机器，在调度。

**2. 免费版必须托管 DNS，解析权被接管。** 这是最要命的一条。云一旦开了小黄云，这条记录的解析就由 Cloudflare 全局控制，你没法按线路分流，没法做多 CDN 互备，也没法把流量精确地导向某个优化节点。想摆脱这个限制，得买付费版走 CNAME 接入（Partial Setup），或者用 Cloudflare for SaaS 自定义主机名绕一圈——都不是「免费方案」该有的复杂度。

**3. 换成其他海外 CDN 也差不多。** Fastly、Bunny、各种「全球加速」服务，要么大陆覆盖同样稀薄，要么要求备案，要么按量计费贵到不敢开。

**4. 那自建 CDN 呢？** GoEdge、CDNfly、Kangle 这类方案自由度最高，调度、缓存、防护全在自己手里。但代价是**控制面也要自己搭**：数据库、面板、证书续签、节点上报、监控告警，一整套运维负担。个人站长的服务器往往只有一两台，为了加速反而先把自己维护垮了。

所以理想形态其实很清楚：

> **像自建 CDN 一样可控，但不用自己搭控制面；用境外节点，所以不需要备案；又能跑出大陆直连的低延迟。**

这正是 AxisNow 想做的事。

## 二、AxisNow 是什么

AxisNow（[axisnow.io](https://www.axisnow.io/zh)）是一个**自托管边缘平台**。它和公共 CDN 最大的不同，是**把边缘基础设施和边缘服务拆开**：

| 组件 | 是什么 | 谁来管 |
| --- | --- | --- |
| **AxisNow Cloud** | 托管的多租户**控制面**（SaaS）。存配置、日志、事件，注册边缘节点，提供 Admin API | 官方 |
| **Edge** | 你环境里的**数据面**。实际代理转发流量、执行插件与规则 | 你自己（或你订阅的提供商） |

这个拆分带来两个直接好处：

- **数据主权**：数据面跑在你自己（或你选定的提供商）的机器上，**流量不在 AxisNow 的服务器上解密**。控制面只拿系统遥测和聚合指标，多租户数据库是分段存储的，每个租户一把独立密钥。
- **组合自由**：控制面统一，边缘节点可以来自不同的人。**节点和调度彻底解耦**——这正是本文要用到的能力。

代理模块用的是**久经考验的 NGINX**，所以性能基线是有保障的。

### 两种玩法：自建，或者订阅

AxisNow 提供两种获得边缘节点的方式：

1. **自建边缘**：自己买 VPS，跑一行安装脚本，节点自动上线。完全掌控，但每台机器都要自己付钱、自己维护。
2. **订阅提供商节点**：在官方的**边缘市场**里，用邀请码订阅别人已经部署好的节点，以 **CNAME 方式**分配给你使用。

对个人站长来说，第 2 种才是真正的甜点——市场上有多家提供商提供**每月免费流量**。

**本文只讲第 2 种。** 自建边缘属于进阶玩法，受众窄、还要额外买机器，就不在本文展开了。

### 一切都插件化

AxisNow 的边缘能力全部做成插件，按需订阅：

| 分类 | 插件 |
| --- | --- |
| 路由管理 | **DNS 路由**（全局流量管理 GTM） |
| 监控与事件 | **边缘拨测**（可用性 + 延迟监控，为 DNS 路由提供决策依据） |
| 连接管理 | SSL/TLS 自动 HTTPS、现代通信协议（HTTP/2、HTTP/3、WebSocket、gRPC）、真实客户端 IP |
| 访问控制 | 通用访问控制、速率控制、GraphQL 访问控制、URL 重定向 |
| 缓存管理 | 缓存控制（自定义缓存 Key / 分片缓存 / 自定义 TTL） |
| 回源控制 | 回源连接控制、回源请求改写、回源健康检查、回源重试 |
| 响应控制 | 响应头改写、自定义错误页面、HTML 改写、内容压缩 |
| 日志与事件 | 访问日志（可转发到第三方日志服务） |

本文会用到其中两个：**DNS 路由**和**边缘拨测**。

## 四、开搞：订阅节点 + 回源接入

整体链路是这样的：

```
访客 → 权威 DNS → AxisNow 调度域 → 地址池(EIP) → 边缘节点 → 回源 → 你的源站
```

一共六步：**集成 DNS 提供商 → 订阅提供商 → 确认节点 → 新增域并配置回源 → 配置 DNS 路由 → 切换主域名解析**。

### 准备工作：创建租户

打开 [dashboard.axisnow.io/signup](https://dashboard.axisnow.io/signup)，用一个域名创建一个租户空间（租户名可以取项目名或公司名）。支持 Google / GitHub / Apple / Microsoft 账号授权登录。

登录后你会看到一个相当现代的仪表板，左侧导航是：**仪表板 / 边缘 / 端点 / 调度 / 策略 / 洞察**。这五块正好对应它的核心概念，再往下我们只会用到其中的四块。

### 步骤 1：集成你的 DNS 提供商

入口在 **设置 → 集成 → DNS 提供商**。**建议放在最前面做，后面整个流程会顺很多。**

这一步的本质，是**把你 DNS 服务商的 API 凭据交给 AxisNow，授权它去读写你 Zone 里的解析记录**。绑定之后，AxisNow 就能替你动手改解析，不用每次都手动登录 DNS 后台。它带来两件事：

1. **解析记录自动写入和更新。** 后面配置调度域、维护优选结果，解析值的变化都可以交给它。
2. **证书的 DNS 验证。** 申请和续期证书时自动写入 `_acme-challenge` 的 TXT 记录完成验证——比 HTTP 验证更适合分区/分线路解析、或境外 CA 不一定能请求到你的 EIP 的场景。

![新增 DNS 提供商：目前支持的六家](/img/posts/axisnow-cdn/01-dns-provider.png)

目前支持 **Cloudflare、阿里云、DNSPod、华为云、Amazon Route 53、ClouDNS** 六家。填一个名称 + **API Token** 即可，保存时平台会立刻用你填的密钥做一次有效性检测。

> **最小权限原则**：在 DNS 服务商的 IAM / RAM 控制台单独建一个子账号或用户，**只授予目标 Zone 的编辑权限**，别图省事直接上主账号密钥；密钥记得定期轮转。

集成列表里还能看到 **24 小时记录同步趋势和异常事件**——以后遇到「解析没生效」这类问题，先看这里。

### 步骤 2：在市场订阅提供商节点

**前往边缘市场**，挑你需要的节点提供商。市场里每一家都会标明擅长区域、防护能力、免费流量和当前订阅人数，每个提供商的详情页都会给出**订阅码**。

![AxisNow 边缘市场的部分免费节点提供商](/img/posts/axisnow-cdn/02-marketplace.png)

拿到订阅码后，回到控制台 **边缘 → 订阅**，把订阅码填进去，绑定成功后这家提供商的节点资源就直接出现在你的列表里了。

整个过程不需要在商家那边另外注册账号，也不需要在你自己的机器上装任何东西——绑定完，对方的节点就已经以 **CNAME 方式**分配给你了。

选择建议：

- 想要**大陆直连** → 优先 AxisNow 官方（阿里云 + 谷歌云，亚欧美都有）和 DeepEdge（回国优化）
- 想要**香港低延迟** → StarVM、AN
- 想要**大流量** → 3Amcloud（1 TB）
- 想要**高防** → AN（5 Tbps+）、DreamCloud（日本高防）

### 步骤 3：确认已订阅的提供商

订阅完成后，进入 **边缘 → 订阅 → 提供商**，就能看到当前生效的提供商列表：

![已订阅 2 个提供商：DeepEdge 与 AxisNow](/img/posts/axisnow-cdn/03-providers.png)

这里有几个信息要留意：

- 每个提供商名下会显示它的 **CNAME 调度域**，那是它分配给你的入口。
- **CNAME 背后的 EIP 分「隐藏」和「公开」两种。** 隐藏型你只能看到 CNAME 地址；公开型你还能看到地址池、路由规则、质量评分和拨测任务，**对应的 EIP 会直接出现在你的 EIP 列表里，可以打标签、自由引用**。
- 上图中 **AxisNow 这一条是「1 CNAME 含 4 可见 EIP」**，属于公开型。这意味着那 4 个 EIP 可以被我们自己的 DNS 路由直接引用——这正是下一步的基础。

> **为什么这很重要？** 在传统 CDN 里，你只能被动接受厂商给你的调度。而在这里，EIP 是**可以拿来自己编排的一等公民**。你既可以让主轴解析到某家的 CNAME，也可以在调度层按线路把流量分配到不同提供商的 EIP 上，甚至把某家整体下线做灰度切换。

### 步骤 4：新增域并配置回源

接下来配置「谁被代理」。进入 **端点 → 域**，点击新增，进入新增域表单：

![新增域：访问域名与回源配置](/img/posts/axisnow-cdn/04-origin.png)

表单分两块：

**① 基础信息** —— 填**访问域名**（访客实际访问的域名，例如 `www.example.com`），并确认监听端口（默认 **80 / 443**）。

**② 回源配置** —— 告诉边缘「请求该转发到哪台源站」：

- **源地址**：填你源服务器的 IP 或域名，可以填一组做负载均衡
- **回源模式**：支持在「**简单模式**」「**按路径回源**」「**按端口回源**」之间切换
  - 常规站点用**简单模式**就够
  - 不同路径要打到不同后端 → 打开**按路径回源**（支持精确与通配符匹配）
  - 需要「回源协议跟随请求」（HTTP→HTTP、HTTPS→HTTPS）或不同端口不同回源 → 用**按端口回源**
- **回源参数**：按端口回源**关闭**时，在这里一次性指定**回源协议（https ://）、回源端口（:443）和回源 Host**。回源 Host 默认跟随访问域名——如果你的源站是靠 Host 头区分站点（比如宝塔、Nginx 多站点），这里别填错

配置完点确认。**证书不用管**：AxisNow 对每个域**默认开启自动 HTTPS**，会自己走 HTTP 验证申请并续签免费证书，到期前自动续期。Edge 节点会直接响应 CA 的校验值。

> 一个容易踩的坑：如果你在权威 DNS 上做了**分区/分线路解析**，要确保**境外的 CA 能请求到你的 EIP** 来完成 HTTP 验证，否则证书会一直申请失败。

**验证方法**：在配置 DNS 之前，先在自己电脑上改 hosts，把访问域名指向任意一个 EIP，看看能不能正常打开。这一步能省掉后面一半的排查时间。

### 步骤 5：配置 DNS 路由（调度域）

到了最关键的一步：**把访客导向哪个 EIP**。

进入 **调度 → DNS 路由**（如果还没订阅，先在插件市场订阅 **DNS 路由** 插件），点「新增」创建调度域：

![新增调度域：AxisNow 托管、选 alidns 后缀、记录类型 A](/img/posts/axisnow-cdn/05-schedule-domain.png)

这一步有三个选择：

- **托管方式**：选 **AxisNow 托管**——官方直接提供调度域名和权威 DNS，**你不需要做任何 DNS 集成**，开箱即用。另一种「自托管」是用你自己的域名和权威 DNS，得先集成 DNS 提供商（见步骤 1）。
- **前缀 + 后缀**：前缀随便填，后缀在 **阿里云** 和 **AWS** 两套免费托管调度域里选一个。**做大陆业务选 alidns**（大陆线路和地理划分更精细），国际业务选 AWS。
- **记录类型**：这里选 **A**（解析到 IPv4 地址）。只有多 CDN 架构才需要 **CNAME**。

点确认后，调度域就会出现在列表里。列表里有两个很实用的列——**24 小时 DNS 同步趋势**（解析有没有在动）和 **24 小时请求趋势**（流量有没有真的过来），排查「配了半天没流量」这类问题时很好用。

另外留意「**EIP 隐藏 / EIP 公开**」的标记。本文订阅的两家正好各占一种：**DeepEdge 是隐藏型**（只能看到调度域名），**AxisNow 是公开型**（EIP 可见、可被引用）。想让自己的调度层能用上这些 EIP，就得依赖公开型。

#### 路由规则：推荐用「优选」

点进调度域，新增路由规则。这里是整套方案真正发力的地方：

![DNS 路由规则：A 记录 + 所有 EIP + Default China Network + 优选](/img/posts/axisnow-cdn/06-dns-route-rule.png)

**① 通用配置**

| 项 | 值 | 说明 |
| --- | --- | --- |
| 记录类型 | **A** | 单集群场景用 A；多 CDN 场景才用 CNAME |
| 线路 | **默认** | 必须先建一条默认线路，这是兜底 |
| TTL | **60 秒** | 故障切换要快，TTL 就得短 |

**② 地址策略 —— 这部分是重点**

- **地址池**：选「**所有 EIP**」。这个选项是**动态**的，页面上写得很清楚：「新增或删除 EIP 会自动同步到这记录」——以后加节点不用回来改规则。

  池子里就是上一步订阅到的那些 EIP，每条都会标明对应的云厂商和来源。

- **地址监控**：选 **Default China Network**（系统预设，含 3 个中国大陆拨测点）。

- **选取策略**：选 **优选**。**这是我最推荐的一个设置。**

  另外两个选项是：**随机**（每次解析随便给一个，纯粹做负载分摊）、**顺序**（按顺序轮询，平均，但不管好坏）。

  而**优选的工作方式是**：

  > AxisNow 用**国内的监测节点**持续拨测地址池里的每一个 IP，测出**从中国大陆访问它们时的真实延迟和可用性**，然后自动挑出**国内访问体验最好的那个地址**，并**动态更新 DNS 解析**。
  >
  > 换句话说：你不需要自己去 ping 各个节点、也不需要在电脑上跑优选工具抄 IP。**加进来一个慢节点，它不会被选中；某个节点在晚高峰开始抽风，解析会自动切走。** 而且这件事是持续发生的，不是配置一次就定死。

  这就是「优选」和传统 CDN 给你一个固定 CNAME 的根本区别——你拿到的不只是一个入口，而是一套**会按大陆实测质量动态调整的解析结果**。

- **地址数量上限**：单次解析最多返回几个地址，图中设的是 **2**。多返回几个可以做客户端侧的兜底，但给太多会稀释「优选」的意图，一般 1~2 个就够。

- **评估周期**：拨测数据的统计窗口，可选 **5 分钟 / 10 分钟**。周期越短切换越灵敏、也越容易抖动；越长越平滑、也越迟钝。图中选了 **10 分钟**，属于偏稳的取向。

> **两个必须知道的坑：**
>
> **坑一：拨测点要和用户线路对齐。** 由于 BGP 多播的特性，用国际拨测点去测一个「大陆优化」的 EIP 会得到完全失真的结果。你的用户在大陆，监控就选大陆拨测点（`Default China Network`）；用户在国际，就选 `Default Intl Network`。
>
> **坑二：默认拨测 URL 只对 AxisNow Edge 有效。** 预设模板请求的是 `https://拨测目标:443/aegis_node_ping/`。**如果你的地址池里放的是非 AxisNow 的地址（比如把 Cloudflare 的 CNAME 也丢进池子里），必须改拨测 URL**，否则那个地址会一直显示红色（异常），并被调度逻辑剔除。

另外，**基于监控的规则有「首次初始化」过程**。监控数据需要一段时间积累，所以**第一次选地址时会忽略监控**。等几分钟，地址池才会变成绿色（正常）或红色（异常）。看到红别慌，先确认是不是上面那两个坑。
### 步骤 6：切换主域名解析

最后一步，去你的权威 DNS 服务商那里，把业务域名用 **CNAME** 指向刚才的调度域：

```
www.example.com.  CNAME  →  <你的调度域>
```

生效后，访客的请求路径就变成了：权威 DNS → 调度域（按线路/延迟选出最优 EIP）→ 边缘节点 → 回源到你的源站。

## 六、结语

把这一整套拆开看，真正解决的问题只有一个：**把「选哪个节点」的权力从 CDN 厂商手里拿回到了自己手上。**

- Cloudflare 免费版够慷慨，但大陆没有 PoP、且必须交出解析权；
- 公共 CDN 配置黑盒、要备案、改规则靠工单；
- 自建 CDN 自由但要自己搭控制面、养机器。

AxisNow 走的是第四条路：**控制面用它的（免运维），数据面用别人的（免成本），调度权留给自己。**

而「订阅制」这个设计最漂亮的地方在于**可组合**——市场上 8 家提供商的免费额度加起来是 2.3 TB，它们各自擅长不同区域和防护能力。你完全可以：

- 大陆线路用 AxisNow 官方的大陆优化 EIP，国际线路用 DreamCloud 或 Moack；
- 把高防的 AN 挂在国际默认线路上当兜底；
- 用**多 CDN 调度**把多家 CNAME 也丢进地址池，靠边缘拨测自动优选和切换。

这些全都建立在同一件事上：**EIP 和 CNAME 是可以在你自己的调度层里自由编排的对象**，而不是被锁死在某个厂商的黑盒里。

**适合谁**：个人博客、文档站、轻量 API、中小团队的官网——流量不大、又确实需要大陆访问体验的场景。

**不适合谁**：图床、视频、网盘这类大流量业务。5 Mb/s 的带宽上限和有限的免费额度撑不住，该上正经的商业 CDN 就上——不过$5/域名/月那一档，作为一个「按域名而非按流量」计费的边缘平台，对成长期业务其实相当划算。

最后提醒一句：本文用到的免费额度**以各提供商页面显示的为准**，商家的政策会变。动手前先看一眼市场页上的最新额度，别照着文章的表格做预算。
